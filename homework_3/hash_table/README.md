# Задача 3. Хеш-таблица

## Условие

Своя хеш-таблица: пары «ключ-значение», вставка, поиск по ключу, удаление.
Хранить значения можно только в `list`.

Нужно решить: как лежат данные, что делать при коллизии, что делать,
когда таблица заполняется.

Код: `solution.py`  
Тесты: `test_hash_table.py`

---

## 1. Объяснение решения

**Как храним данные.**  
Массив корзин: `list` длины `capacity`. В каждой корзине тоже `list`
пар `[ключ, значение]`. Встроенный `dict` не используем.

**Хеш и индекс корзины.**  
`index = hash(key) % capacity`. Python-хеш подходит для чисел и строк.

**Коллизии.**  
Два ключа могут дать один индекс. Тогда оба живут в одной корзине —
это метод цепочек. Поиск в корзине идёт линейно по её списку.

**Вставка `put`.**  
Считаем индекс, ищем ключ в цепочке. Если есть — меняем значение
(размер не растёт). Если нет — дописываем `[key, value]` в корзину.

**Поиск `get` и удаление `delete`.**  
Та же корзина, тот же проход. Нет ключа — `KeyError`.

**Рост таблицы.**  
Если после вставки `size / capacity > 3/4`, удваиваем число корзин
и раскладываем все пары заново. Иначе длинные цепочки и поиск
деградирует к `O(N)`.

**Некорректный ввод.**  
Ёмкость `< 1` — `ValueError`. Отсутствующий ключ в `get`/`delete` —
`KeyError`, а не `None`.

---

## 2. Оценка сложности

Пусть `N` — число пар, `C` — число корзин.

В среднем цепочка короткая (длина около `N / C`):

- **Вставка / поиск / удаление:** среднее `O(1)`, худшее `O(N)`,
  если все ключи попали в одну корзину.
- **Память:** `O(C + N)` — массив корзин плюс все пары.
- **Перехеширование:** `O(N)` раз, но редко. Амортизированно вставка
  остаётся `O(1)`.

Порог `3/4` держит среднее число элементов в корзине небольшим.

## 3. Визуализация работы алгоритма

Ёмкость 4, чтобы коллизия была сразу видна. Берём ключи `0` и `4`:
у целых `hash(n) = n`, оба индекса `0` и `4 % 4 = 0`.

Старт: четыре пустые корзины.

```text
[0]: []
[1]: []
[2]: []
[3]: []
```

**put(0, "a")** — индекс 0:

```text
[0]: [[0, "a"]]
[1]: []
[2]: []
[3]: []
```

**put(1, "b")** — индекс 1:

```text
[0]: [[0, "a"]]
[1]: [[1, "b"]]
[2]: []
[3]: []
```

**put(4, "c")** — индекс 0, коллизия, пара в ту же цепочку:

```text
[0]: [[0, "a"], [4, "c"]]
[1]: [[1, "b"]]
[2]: []
[3]: []
```

**get(4)** — корзина 0, пропускаем ключ `0`, берём `"c"`.

**put(0, "A")** — ключ `0` уже есть, меняем значение, размер тот же:

```text
[0]: [[0, "A"], [4, "c"]]
```

**delete(0)** — вычёркиваем первую пару из корзины 0:

```text
[0]: [[4, "c"]]
[1]: [[1, "b"]]
```

`get(4)` по-прежнему `"c"`: удаление соседа по цепочке его не трогает.

Дальше, когда пар станет больше `3/4` от ёмкости, появится 8 корзин,
и `0` с `4` разъедутся: `0 % 8 = 0`, `4 % 8 = 4`.
