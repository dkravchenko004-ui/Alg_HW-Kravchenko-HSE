# Задача 3. K-th

## Условие

Найти k-й по величине элемент массива. Нельзя просто отсортировать.
Кучи не используем. Подсказка: quickselect.

Примеры: `[3, 2, 1, 5, 6, 4]`, `k = 2` → `5`;
`[3, 2, 3, 1, 2, 4, 5, 5, 6]`, `k = 4` → `4`.

Код: `solution.py`  
Тесты: `test_kth.py`

---

## 1. Объяснение решения

k-й по величине — это элемент на позиции `N - k`, если смотреть
на массив **после** сортировки по возрастанию. Считать всю сортировку
не нужно: после одного разбиения quicksort опорный уже стоит на своей
итоговой позиции `p`.

- если `p == N - k` — это ответ;
- если `p` правее нужного индекса — ответ слева, правую часть
  отбрасываем;
- если левее — идём только вправо.

Разбиение как на лекции: опорный последний, меньшие слева, большие
или равные справа. Дальше цикл, не рекурсия: сужаем `lo` и `hi`.

Полный `sorted(nums)` и `heapq` в решении нет. Копия входа нужна,
чтобы не портить исходный список.

**Некорректный ввод.** Не целые / не последовательность / нецелое `k` —
`TypeError`. Пустой массив, `k < 1` или `k > N` — `ValueError`.

---

## 2. Оценка сложности

Пусть `N` — длина.

В среднем каждый шаг отбрасывает половину, время `O(N + N/2 + N/4 + ...) = O(N)`.
В худшем (уже отсортированный вход, опорный последний) отрезается
один элемент, время `O(N^2)`.

Память `O(N)` на копию массива и `O(1)` сверх неё: цикл, не стек
рекурсии. Кучу не выделяем.

Полная сортировка была бы `O(N log N)` всегда. Здесь в типичном случае
быстрее, но без гарантии худшего случая — для ДЗ этого достаточно,
медиана медиан на курсе не требуется.

## 3. Визуализация работы алгоритма

Пример из условия: `nums = [3, 2, 1, 5, 6, 4]`, `k = 2`.
Ищем 2-й максимум. По возрастанию это индекс `6 - 2 = 4`
(0-based): числа `[1, 2, 3, 4, 5, 6]`, на месте 4 стоит 5.

```text
[3, 2, 1, 5, 6, 4]     pivot=4, target=4
меньше 4: 3, 2, 1
остальные направо
после partition:  [3, 2, 1, 4, 6, 5]   p=3

p=3 < 4 → ответ правее, берём [6, 5]

[6, 5]                 pivot=5
6 >= 5 → остаётся справа
после partition:  [..., 5, 6]          p=4

p == target → ответ 5
```

Вторую половину `[3, 2, 1, 4]` больше не трогаем: для 2-го максимума
она не нужна. В этом и отличие от полной сортировки.

Второй пример, `k = 4` в `[3, 2, 3, 1, 2, 4, 5, 5, 6]`:
по убыванию `6, 5, 5, 4, ...` — четвёртый как раз 4. Повторы
обрабатываются тем же разбиением: равные опорному уходят вправо.
