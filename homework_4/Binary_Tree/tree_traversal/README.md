# Задача 1. Tree Traversal

## Условие

Реализовать бинарное дерево поиска (BST) и вставку с сохранением свойства BST.
Реализовать шесть обходов: preorder, inorder, postorder, reverse preorder,
reverse inorder, reverse postorder. Каждый обход возвращает список значений
узлов в порядке посещения.

Код: `solution.py`  
Тесты: `test_tree_traversal.py`

---

## 1. Объяснение решения

**BST.** У каждого узла ключи в левом поддереве строго меньше него, в правом —
больше или равны. Равные значения кладём направо, чтобы правило было однозначным.

**Вставка.** Идём от корня: меньше текущего — налево, иначе направо. Когда
упираемся в пустое место, вешаем новый узел. Рекурсия возвращает ссылку на
поддерево, поэтому родитель подхватывает нового ребёнка.

**Обходы.** Это один и тот же обход дерева, меняется только порядок трёх
действий: обработать узел (`N`), пойти налево (`L`), пойти направо (`R`).

| Обход              | Порядок | Зачем смотреть |
| ------------------ | ------- | -------------- |
| preorder           | N, L, R | «сначала корень» |
| inorder            | L, N, R | в BST получается возрастание |
| postorder          | L, R, N | дети, потом корень |
| reverse preorder   | N, R, L | preorder, но сначала правое |
| reverse inorder    | R, N, L | в BST получается убывание |
| reverse postorder  | R, L, N | postorder, но сначала правое |

Обратные обходы — это обычные, у которых левое и правое поменяли местами
(как на [вики обходов](https://en.wikipedia.org/wiki/Tree_traversal)).

Пустое дерево даёт `[]`. Один узел — список из него самого.

**Некорректный ввод.** Нецелое значение при вставке — `TypeError`.
`bool` не считаем целым числом.

---

## 2. Оценка сложности

Пусть `N` — число узлов, `H` — высота дерева.

- **Вставка одного ключа:** время `O(H)`, память рекурсии `O(H)`.
В среднем на случайных данных `H ~ log N`, в худшем дерево вытягивается
в цепочку и `H = N`.
- **Каждый обход:** время `O(N)` — каждый узел посещаем один раз.
Память `O(N)` на ответ плюс `O(H)` на стек рекурсии.

## 3. Визуализация работы алгоритма

Вставляем `8, 3, 10, 1, 6, 14, 4, 7`. Это не цепочка и не идеально
сбалансированное дерево — на нём видно и левые, и правые ветки.

```text
insert 8          8

insert 3          8
                 /
                3

insert 10         8
                 / \
                3   10

insert 1          8
                 / \
                3   10
               /
              1

insert 6          8
                 / \
                3   10
               / \
              1   6
```

Дальше `14` уходит вправо от `10`, `4` и `7` — дети шестёрки:

```text
            8
           / \
          3   10
         / \    \
        1   6    14
           / \
          4   7
```

Preorder (корень, левое, правое): спускаемся «вглубь налево», корень
пишем сразу.

```text
8 => левое(3 => 1 => 6 => 4 => 7) => правое(10 => 14)
[8, 3, 1, 6, 4, 7, 10, 14]
```

Inorder (левое, корень, правое): сначала всё, что меньше, потом узел.

```text
1, 3, 4, 6, 7, 8, 10, 14
```

Это те же ключи по возрастанию — так проверяют, что вставка не сломала BST.

Postorder (левое, правое, корень): `1, 4, 7, 6, 3, 14, 10, 8`.

Reverse preorder — как preorder, но сначала правая ветка:

```text
8 => правое(10 => 14) => левое(3 => 6 => 7 => 4 => 1)
[8, 10, 14, 3, 6, 7, 4, 1]
```

Reverse inorder: `14, 10, 8, 7, 6, 4, 3, 1` — ключи по убыванию.

Reverse postorder: сначала правое поддерево, потом левое, потом корень
`14, 10, 7, 4, 6, 1, 3, 8`.
