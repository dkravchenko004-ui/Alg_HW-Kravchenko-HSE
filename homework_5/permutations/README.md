# Задача 2. Permutations

## Условие

Дан массив. Вернуть все возможные перестановки.

Примеры: `[1, 2, 3]` => шесть списков, `[0, 1]` => `[[0, 1], [1, 0]]`,
`[1]` => `[[1]]`.

Рекурсию оборачиваем декоратором `trace` из задачи 1.

Код: `solution.py`  
Тесты: `test_permutations.py`

---

## 1. Объяснение решения

Идём вглубь: на каждом шаге в `path` лежит уже выбранный префикс.
Смотрим элементы исходного массива по индексам. Кто ещё не в `used` —
берём, помечаем, вызываем `generate(path + [значение])`, потом снимаем
пометку (обычный откат).

Когда длина пути равна длине массива — это одна перестановка. Функция
возвращает список найденных перестановок, чтобы в трассировке на выходе
был результат, а не `None`.

Порядок как в примере: сначала все перестановки, начинающиеся с первого
элемента, потом со второго, и так далее.

Пустой массив даёт `[[]]`: одна перестановка из нуля элементов.

---

## 2. Оценка сложности

Пусть `N` — длина массива.

Перестановок `N!`, каждая длины `N`.

- **Время:** `O(N * N!)`. Каждую перестановку собираем и копируем.
- **Память:** `O(N * N!)` на ответ плюс `O(N)` на `path`, `used` и стек
рекурсии.

Печать трассировки добавляет работу пропорционально числу вызовов
`generate`. Их тоже `O(N!)`, асимптотику ответа это не улучшает и не
ухудшает.

---

## 3. Визуализация работы алгоритма

Разбор `[1, 2]` целиком (для `[1, 2, 3]` дерево такое же, только шире).
Это вывод декоратора `trace`:

```text
-> generate([])
  -> generate([1])
    -> generate([1, 2])
    <- generate([1, 2]) = [[1, 2]]
  <- generate([1]) = [[1, 2]]
  -> generate([2])
    -> generate([2, 1])
    <- generate([2, 1]) = [[2, 1]]
  <- generate([2]) = [[2, 1]]
<- generate([]) = [[1, 2], [2, 1]]
```

Стартуем с пустого пути. Сначала берём `1`, затем единственный остаток
`2` — готовая перестановка. Откат, берём `2`, затем `1`. Наверху обе
половины склеиваются.
